# Models

All data required to work effectively with a specific model family or model: operating profile, capabilities, limits, supported tools, configuration contract, compatibility notes, evaluated tasks, prompts or skills that are specific to that model, and version/change history.

Example structure:

```
05_MODELS/
└── CLAUDE/
    ├── claude.md
    ├── capabilities.md
    ├── configuration.md
    ├── compatibility.md
    └── evaluation/
```

A model directory is model-specific working knowledge. It does not store provider credentials, private keys, unlicensed weights or unverified performance claims.
